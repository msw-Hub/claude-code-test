# 코드 스타일 및 컨벤션

## 단일 파일 구조 (의도된 제약)

`index.html` 하나에 HTML·CSS·JS를 모두 인라인으로 담는다. 아래는 유지해야 할 설계 원칙이다:

- **외부 리소스 의존 제로.** 폰트는 시스템 폰트 스택(`-apple-system, ... "Noto Sans KR"`),
  아바타는 이미지 파일이 아니라 CSS 그라데이션. CDN·웹폰트·외부 이미지·외부 스크립트를 추가하지 말 것.
  오프라인에서 파일 하나만으로 완전히 렌더링되는 상태를 깨지 않는다.
- **파일을 쪼개지 않는다.** CSS/JS를 별도 파일로 분리하면 배포(루트 정적 서빙) 이점이 사라지고
  구조만 복잡해진다. 규모가 커지기 전까지는 한 파일 유지.

## CSS

- **디자인 토큰 우선.** 색상·본문 폭 등은 `:root`의 CSS 변수 한 곳에서 관리한다.
  색을 직접 하드코딩하지 말고 기존 토큰(`--bg`, `--surface`, `--text`, `--accent` 등)을 쓰거나
  새 토큰을 추가할 것.
- **간격은 섹션 단위 수직 리듬을 따른다.** `section { padding: 72px 0 }` 처럼 일관된 리듬이 있으니
  새 섹션도 이 패턴에 맞춘다.
- **반응형 분기는 최소로.** 현재 `@media (max-width: 520px)` 하나뿐이다. 꼭 필요할 때만 늘린다.
- 각 CSS 규칙 블록 위에 **그 스타일이 왜 필요한지**(정렬·간격·반응형·시각적 구분 등) 짧은 주석을 단다.
  기존 `index.html`의 주석 밀도와 어조를 그대로 따를 것.

## JavaScript

- 바닐라 JS만 사용. 프레임워크·빌드 없음. ES5~ES6 수준의 브라우저 네이티브 API로 작성.
- **스크롤 등장 효과는 `IntersectionObserver`로 처리한다.** 스크롤 이벤트 리스너 방식이 아니다
  (매 스크롤마다 위치 계산 → 성능 부담, 코드 복잡). 새 섹션은 `class="reveal"`만 붙이면
  옵저버가 자동으로 `.is-visible`을 토글한다. 한 번 나타난 요소는 `unobserve`로 관찰을 해제한다.
- 각 함수/콜백 위에 그게 **무엇을 하는지** 한 줄 주석.

## 설명을 어디에 쓸지 (중복 방지)

- 그 코드를 읽을 때만 필요한 지엽적 결정 → **코드 주석**
- 여러 파일·구조 전반에 걸친 결정 → **채팅 설명** (또는 이 rules 문서)
- 한쪽에 이미 쓴 내용을 다른 쪽에서 반복하지 않는다.

## 언어

- UI 문구·주석·커밋 메시지는 한국어.
- 코드 식별자, 기술 용어는 원문 유지.
